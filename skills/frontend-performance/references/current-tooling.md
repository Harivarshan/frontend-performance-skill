# Frontend build and CI tooling

Documentation checked 2026-11-24. Verify the versions, runner, event, and configuration used by the measured job before applying a default from these docs.

## GitHub Actions

- Record the repository, workflow `run_id`, `run_attempt`, and the API job ID. Reruns keep the run ID and increment the attempt. List jobs with `GET /repos/{owner}/{repo}/actions/runs/{run_id}/attempts/{attempt_number}/jobs` to get the selected attempt's jobs and step timestamps. Fetch logs by the job ID and retain the matrix axes when comparing jobs. The run-level jobs endpoint defaults to `filter=latest`. [Contexts](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#github-context), [Jobs API](https://docs.github.com/en/rest/actions/workflow-jobs#list-jobs-for-a-workflow-run-attempt)
- For `actions/cache`, record the resolved key, archive paths, and cache version. GitHub derives the version from the paths and compression tooling. `cache-hit: true` signals an exact primary-key match. A fallback can restore files, so inspect the logs to see what was restored and the build output to see what the tool reused. Existing entries are immutable. [Dependency caching](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching), [Cache action outputs](https://github.com/actions/cache#outputs)
- Check the event and ref on both producer and consumer. GitHub permits restores from the current and default branches, with base-branch access for PRs. A cache saved under a PR merge ref is only available to that PR's reruns. Events such as `pull_request_target` and `issue_comment` running on the default branch normally get read-only access to that scope. Use a trusted producer such as a default-branch `push` and confirm it actually saved the entry. [Cache access restrictions](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching#restrictions-for-accessing-a-cache)

## Docker BuildKit

- Check the builder driver and both `--cache-from` and `--cache-to`. The default `docker` driver requires the containerd image store for the `inline`, `local`, `registry`, and `gha` backends. Inline export supports `min`; a separate registry cache or `gha` can use `mode=max` to include intermediate stages. Compare cached steps, build time, and import/export time. Give independent image builds distinct registry refs or `gha` scopes so their exports do not replace one another. [Cache backends](https://docs.docker.com/build/cache/backends/), [GitHub Actions cache backend](https://docs.docker.com/build/cache/backends/gha/)
- `RUN --mount=type=cache` keeps a directory on the builder, useful when the step runs again. A fresh builder using the `gha` backend does not get that mount's contents by default. Verify mount persistence separately from layer reuse and test with an empty mount. Check GitHub Cache service API v2 support on pinned or self-hosted builders and confirm write access for the workflow's event and ref. [Dockerfile cache mounts](https://docs.docker.com/reference/dockerfile/#run---mounttypecache), [Cache management in GitHub Actions](https://docs.docker.com/build/ci/github-actions/cache/)

## Next.js and TypeScript

- Check the effective `next build` command and installed Next.js version. Next.js 15.5 offered production Turbopack through `--turbopack` as beta. Next.js 16 made Turbopack the build default, with `--webpack` available for projects that still need Webpack. Next.js 16 also removed linting from `next build`. Verify bundler compatibility and keep the project's required lint check in CI. [Next.js 15.5 release](https://nextjs.org/blog/next-15-5#turbopack-builds-beta), [Next.js 16 upgrade guide](https://nextjs.org/docs/app/guides/upgrading/version-16)
- Preserve `.next/cache` in the build workspace when testing cross-run reuse, including inside the build container when applicable. Turbopack filesystem caching defaults on for development from 16.1 and for production builds from 16.3. Check the build setting for earlier versions and time cache transport alongside the build. [CI build caching](https://nextjs.org/docs/app/guides/ci-build-caching), [Turbopack filesystem cache](https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopackFileSystemCache)
- `next build` fails on TypeScript errors by default. If testing a separate required type check, `next typegen` (added in 15.5) generates route types and `next-env.d.ts` without a full build. Run it before `tsc --noEmit` with the same TypeScript config the build uses and check that failures still block delivery before changing `ignoreBuildErrors`. For incremental TypeScript, locate the effective `.tsbuildinfo` path and measure its reuse separately from bundler cache reuse. [Next.js TypeScript config](https://nextjs.org/docs/app/api-reference/config/next-config-js/typescript), [Next.js CLI](https://nextjs.org/docs/app/api-reference/cli/next#next-typegen-options), [TypeScript incremental](https://www.typescriptlang.org/tsconfig/incremental.html)

## Playwright Test

- Inspect `webServer.command`, its working directory, and the readiness check. `reuseExistingServer` can attach tests to an already listening server. For CI, verify the server serves the intended revision and measure startup through the first test route response, especially if that route compiles on demand. [Web server](https://playwright.dev/docs/test-webserver)
- `--shard=i/n` distributes files by default. `fullyParallel: true` allows test-level distribution and balances by test count. Compare elapsed shard times and check test isolation before enabling it. Include repeated setup and the job that merges blob reports in the total. [Sharding](https://playwright.dev/docs/test-sharding), [Parallelism](https://playwright.dev/docs/test-parallel)
- A failed test causes Playwright to replace the worker and browser. With retries enabled, the replacement worker retries the test, and a pass on retry is reported as flaky. Track first-attempt failures, retry time, and worker setup alongside shard duration. Keep retry policy fixed when comparing another change. [Retries](https://playwright.dev/docs/test-retries)
